# Contributing to Pictorium

Thanks for your interest! Before opening a PR, please read these guidelines.

## Setup

```bash
npm install
npm run dev
```

You need a TMDB key (variable `PICTORIUM_TMDB_KEY`, see `README.md` → Environment Variables) for real catalogs and renders. Tests use a mock server and require no keys.

## Main commands

| Command | Purpose |
|---|---|
| `npm run verify` | Typecheck + lint + unit tests + build — **run before every PR** |
| `npm run test` | Unit tests (Vitest) |
| `npm run test:coverage` | Unit tests with coverage |
| `npm run e2e:visual` | Visual regression (Playwright, reuses `.next-e2e`) |
| `npm run e2e:visual:clean` | Visual regression with a clean E2E build |
| `npx playwright test e2e/` | Full Playwright suite |
| `node scripts/load-smoke.mjs` | Load smoke test of the render pipeline |

## Project rules

1. **Client ↔ server in sync** — the client preview (WYSIWYG) and the final Stremio poster must render the exact same image. Every visual parameter (geometry, gradients, badges, logo, etc.) must be updated on both sides. See `.agents/render-params.md`.
2. **Single renderer** — do not duplicate the rendering logic: the `/api/poster/{type}/{id}` endpoint serves both the preview and the final poster.
3. **Visual regression** — if you change code that affects the visual output, run `npm run e2e:visual` and inspect the snapshot diffs: update snapshots only if the visual change is intentional.
4. **Generated files** — `APP_VERSION` and `RENDER_VERSION` are generated by the `scripts/write-app-version.mjs` / `scripts/write-render-version.mjs` scripts (they are regenerated automatically by `predev`/`prebuild`/`pretest`). Do not edit them by hand.
5. **Public contracts** — API routes, URL parameter names and semantics, response formats, and environment variable names are public contracts: do not change them without an explicit reason.
6. **Minimal changes** — one PR solves one problem: no unrequested refactors, no new dependencies without need.

## PR guidelines

- One topic per PR; the final diff must contain only justified changes.
- In the PR body, describe what you changed, which checks you ran, and whether the visual output changed (with updated snapshots in that case).
- Project documentation (`AGENTS.md`, `.agents/*.md`) is intentionally in Italian; code and comments are in English.
